# AGENTS

## 协作约定

- 默认直接实现，不用反复确认。
- 可以直接修改项目文件并运行 `npm run build` 做验证。
- 除非涉及删除文件、覆盖用户未说明要改的内容、或其他明显破坏性操作，否则不用先询问。
- 输出和说明默认使用中文，保持简洁，重点说清改动和验证结果。

## 项目结构约定

- 这是一个基于 Vite 的 Three.js 单页示例项目，统一从 `src/main.js` 进入。
- 页面模块放在 `src/pages/`，命名使用 `xxx.js`。
- 共享示例数据和预览逻辑放在 `src/components/<topic>/`。
- 路由使用 hash 路由，静态页直接注册在 `src/main.js`，详情页通过正则解析 `#/topic/:id`。

## 页面编写规范

- 总览页优先遵循现有模块模式：说明文案 + 卡片网格 + 预览区 + 详情入口。
- 详情页优先遵循现有模块模式：返回链接 + 标题说明 + 大画布舞台 + 代码/参数说明区。
- 新增模块时，优先保持和 `materials`、`textures`、`lights` 页面一致的结构和命名风格。
- 页面内局部样式可以内联在 `container.innerHTML` 的 `<style>` 中，延续当前仓库写法。

## Three.js 编写规范

- 场景初始化、相机、灯光、几何体、材质、动画循环、销毁逻辑要写清边界。
- 进入新路由时负责挂载，离开路由时必须停止动画、移除事件监听、释放 renderer 和相关 WebGL 资源。
- 能复用的预览逻辑优先提取到 `src/components/<topic>/`，避免页面文件塞满具体渲染细节。
- 同类对比示例尽量复用同一组物体或舞台，让差异集中在当前教学主题本身。
- 窗口尺寸变化时必须同步更新 renderer 尺寸和相机投影矩阵。

## 代码风格

- 默认使用原生 ES module，不引入额外框架或状态管理。
- 保持 ASCII 优先；只有文件本来就是中文文案场景时才使用中文字符串。
- 注释保持克制，只在场景搭建、资源释放、共享 renderer、多视口等不直观逻辑附近补充说明。
- 不做与当前需求无关的大规模重构。
- 不修改与当前任务无关的现有未提交改动。

## 验证规范

- 完成实现后至少运行一次 `npm run build`。
- 如果新增了路由或页面，需要额外检查对应 hash 路径是否能正常进入和返回。
- 在没有现成自动化测试框架时，以构建通过和手工路由验证作为基础验收。

## 沙箱执行约定

- 为减少 Windows 沙箱审批触发，新增或修改文件时优先使用 pply_patch，避免复杂重定向、heredoc、动态脚本批量写入。
- Shell 命令尽量保持简单、稳定、路径明确，优先在项目根目录下使用相对路径，例如 src/pages/xxx.js。
- 新增目录时优先使用明确的 New-Item -ItemType Directory -Force 'src\\components\\topic' 形式，避免跨盘或混合绝对路径。
- 如果沙箱仍因 Access denied、网络限制或 sandbox refresh 失败而拦截，可以按工具要求申请提升权限；这是运行环境限制，不代表需要重新确认需求。
- 不要为了绕过审批改用更危险或更宽泛的命令；必要授权应说明具体文件或目录和目的。
